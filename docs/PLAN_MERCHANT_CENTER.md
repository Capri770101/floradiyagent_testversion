# 商家中心重构开发计划（商家后台产品设计对齐 · 参考美团商家后台）

> 文档性质：规划与任务清单。依据用户对美团商家后台截图的分析结论——**商家后台是独立经营工具，不混入客户端页面，且必须保留与顾客沟通的闭环**。
> 生成日期：2026-08-18 · 状态：待执行

---

## 0. 沿用红线（最高约束）

- **红线1 · 完成标准**：功能按可上线标准交付；DB 结构先建好，缺失数据用 seed 填充（可清空重灌）；不允许空壳/占位。
- **红线2 · 数据纪律**：前端每处展示字段必须有真实后端来源；改库结构同步更新 seed 与契约文档（`docs/FIELD_CONTRACT.md`）。

---

## 1. 现状体检（商家后台偏离经营工具原则的差距）

| # | 位置 | 问题 | 严重度 |
|---|------|------|--------|
| G1 | `Merchant.jsx:528` 工作台「查看门店」 | 跳 C 端 `/shop/{id}` 店铺页 | P1 |
| G2 | `Merchant.jsx:638` 商品管理「预览店铺」 | 跳 C 端 `/shop/{shopId}` | P1 |
| G3 | `Merchant.jsx:892` 店铺设置「预览店铺」 | 跳 C 端 `/shop/{id}` | P1 |
| G4 | `Merchant.jsx:179` 订单卡「查看物流」 | 跳 C 端 `/logistics/{order_id}`（商家看顾客视角页） | P1 |
| G5 | 评价管理（`merchant_reviews`） | 商家只能看评价，**不能回复**（`reviews` 表无 `reply` 列） | P0 |
| G6 | 商家-顾客沟通 | **完全缺失**：无会话表、无聊天端点、无未读机制 | P0 |
| G7 | 顾客端入口 | 店铺页/订单页无「联系商家」入口，沟通无法发起 | P0 |

设计原则（美团参考）：商家后台所有操作留在 `/merchant` 内完成；「预览」以弹层呈现而非跳转；商家与顾客通过会话系统双向沟通。

## 2. 阶段划分与任务清单

### 阶段0 · 契约先行（基建）

- 更新 `docs/FIELD_CONTRACT.md`：新增「商家-顾客会话」与「评价回复」字段契约（表结构、端点、前端字段来源），作为红线2标尺。

### 阶段1 · 后端（DB + 端点）

| 任务 | 改动文件 | 内容 | 验收 |
|------|----------|------|------|
| T1-1 评价回复列 | `storage/db.py` | `reviews` 表加 `reply TEXT`、`reply_at TEXT`（`_ALTERS` 迁移，兼容旧库） | 旧数据不丢，新列可写 |
| T1-2 会话表 | `storage/db.py` | 新表 `shop_chats`（id, shop_id, user_id, last_msg, last_at, unread_user, unread_merchant, created_at）与 `chat_messages`（id, chat_id, sender user/merchant, content, created_at）+ `_ALTERS` 迁移 | 建表成功、迁移幂等 |
| T1-3 商家端点 | `routers/merchant.py` | `GET /merchant/chats`（会话列表+未读数+顾客昵称，按绑定店铺隔离）、`GET /merchant/chats/{id}/messages`（读取即清商家未读）、`POST /merchant/chats/{id}/messages`（商家发送）、`POST /merchant/reviews/{id}/reply`（写回复） | 端点返回契约字段，权限隔离生效 |
| T1-4 顾客端点 | `routers/*`（新建 `routers/chats.py`） | `GET /chats/shop/{shop_id}`（取或建会话）、`GET/POST /chats/{id}/messages`（顾客读取清用户未读/发送） | 顾客可发起并回复 |
| T1-5 演示数据 | `scripts/seed_demo.py` | 灌 1 组演示会话（capri_demo ↔ S001，顾客 2 条 + 商家 1 条回复）与 1 条带回复评价 | 商家/顾客端均有可见数据 |

### 阶段2 · 前端商家端（`Merchant.jsx`，全部留在 /merchant 内）

| 任务 | 内容 | 验收 |
|------|------|------|
| T2-1 去客户端跳转 G1-G3 | 「查看门店/预览店铺」改为**商家内部预览弹层**（复用 `stats.shops` 数据渲染店铺资料卡，不出 /merchant） | grep 无 `nav('/shop/` |
| T2-2 去客户端跳转 G4 | 订单卡「查看物流」改为**商家端物流时间线展开**（复用物流管理时间线组件） | grep 无 `nav('/logistics/` |
| T2-3 顾客会话 Tab | 新增 Tab「顾客会话」：会话列表（顾客昵称/店铺/最后消息/时间/未读红点）→ 会话详情聊天界面（气泡 + 输入发送 + 定时轮询） | 会话闭环可见，未读红点正确 |
| T2-4 订单联系顾客 | 订单卡加「联系顾客」→ 直达该订单顾客会话（无会话则按 `order.user_id` 创建） | 点按直达会话并带订单上下文 |
| T2-5 评价回复 | 评价管理：每条评价展示/编辑商家回复（`reply` 回显 + 回复按钮 + 回复时间） | 回复写入后端并回显 |

## 3. 执行顺序

1. **P0（沟通闭环基座）**：阶段0 契约 → T1-1/T1-2（表）→ T1-3/T1-4（端点）→ T1-5（seed）
2. **P1（商家端）**：T2-1~T2-2（去跳转）→ T2-3（会话 Tab）→ T2-4/T2-5
3. **P1（顾客端）**：T3-1~T3-3
4. **P2（保障）**：T4-1~T4-4

建议起点：阶段0 + T1-1 + T1-2 + T1-3（一条线打通后端闭环）。

---

## 4. 验收口径

- **红线1**：会话与评价回复全链路可用；seed 有演示数据；无空壳。
- **红线2**：`Merchant.jsx` 内无 `nav('/shop/`、`nav('/logistics/`；会话消息/未读数/回复均来自后端；契约文档已更新。
- **一致性门禁**：`pytest` + `npm test` + `lint` + `build` 全绿方可。

---

## 5. 不在本阶段范围

- 会话附件/图片消息（仅文本）、消息推送（无 WebSocket，用轮询）、敏感词过滤。
- 商家多客服账号体系（会话挂在店铺维度，商家账号共用）。
